# PR-002: Live queue gauges via QueueGaugeUpdater

Branch: pr-002-queue-gauge-updater
- Type: feature
- Complexity: low
- Depends on: PR-001
- Priority: 2
- Coder: any

## Problem

Sprint 4 created four queue state gauges (`queue_pending_count`, `queue_processing_count`, `queue_sent_count`, `queue_failed_count`) on `MetricsRegistry`, but no code ever calls `.set()` on them. Prometheus scrapes show `0.0` forever, so dashboards and alerts on queue depth are broken. Operators have no visibility into whether items are stuck in `processing/` or accumulating in `failed/`.

A periodic task that scans the four state subdirectories and updates the gauges is the simplest way to keep them honest. Since SMS volume is 1-2 messages/month and `state/` typically holds < 100 files, a 30-second polling interval is fine — no need for filesystem watchers or live increment hooks scattered across `Queue` methods.

## Scope

Add a `QueueGaugeUpdater` class that periodically counts `*.json` files in each of `state/{pending,processing,sent,failed}/` and pushes the counts into the four gauges. Wire it into the FastAPI lifespan from PR-001 so it starts and stops with the relay.

Add a public `Queue.state_dirs()` method so the updater can read the directory mapping without touching `_dirs_or_raise`. This mirrors the encapsulation cleanup pattern from sprint 5b's `Queue.move_back_to_pending`.

Out of scope: live histogram updates, gauge updates from inside `Queue` mutation methods, retention cleanup (PR-003).

## Files to modify

`src/sms_gateway_v2/queue/queue.py`:
- Add `def state_dirs(self) -> dict[str, Path]` returning a copy of `self._dirs_or_raise()`. Raises `QueueError` if not initialized.

`src/sms_gateway_v2/metrics/gauge_updater.py` (new):
- `class QueueGaugeUpdater` with `__init__(queue, metrics, interval_seconds)`.
- `_stop_event: asyncio.Event`.
- `async def run(self) -> None`: loop until stop event. Each iteration calls `_update_gauges()`, then `await asyncio.wait_for(self._stop_event.wait(), timeout=self._interval_seconds)` wrapped in `suppress(TimeoutError)`. The timeout is the normal idle path.
- `async def _update_gauges(self) -> None`: get dirs via `self._queue.state_dirs()`. For each of pending/processing/sent/failed, count `*.json` files via `asyncio.to_thread(_count_json_files, dirs[name])`. Update the four gauges. Wrap the body in `try/except Exception` and log `gauge_update_failed` on errors so a transient FS issue does not kill the loop.
- `def stop(self) -> None`: sets the stop event.

`src/sms_gateway_v2/relay/factory.py`:
- Change return type from `SmsRelay` to `tuple[SmsRelay, QueueGaugeUpdater]`. Build the gauge updater with `interval_seconds=settings.queue_gauge_interval_seconds` and the same `queue` and `metrics` instances passed to `SmsRelay`.

`src/sms_gateway_v2/app.py`:
- Lifespan startup: after `relay.start()`, spawn `gauge_task = asyncio.create_task(gauge_updater.run())`. Store on `app.state`.
- Lifespan shutdown: BEFORE `relay.stop()`, call `gauge_updater.stop()` and await `gauge_task` with `asyncio.wait_for(..., timeout=2.0)`; on `TimeoutError` cancel the task. Stopping the updater first avoids reading from a queue that is about to close.

## Implementation notes

Stop the gauge updater BEFORE the relay. The relay closes the queue during stop; if the gauge updater is still running, it will read from a closed queue and log a spurious `gauge_update_failed` with `QueueError("queue is not initialized")`. Confusing for operators reading the log of a normal shutdown.

Use `asyncio.to_thread` for the directory scan even though the `state_dir` is small. The worker uses the same directories for atomic file moves; running scans on the default executor avoids contention with the main loop during a delivery burst.

Gauges expose `.set(value)` directly. No labels on these four gauges — keep the existing signature.

## Success criteria

1. `scripts/ci.sh` exits 0.
2. `Queue.state_dirs()` is the only place outside `Queue` that obtains the directory mapping; `gauge_updater.py` does not access `_dirs_or_raise`.
3. With the relay running, dropping a file into `state/pending/` causes `queue_pending_count` to reflect the new count within `queue_gauge_interval_seconds + 1`.
4. The updater survives a transient `OSError` in one iteration without exiting the loop.
5. Lifespan shutdown stops the updater before stopping the relay.
