# PR-004: /state HTTP endpoint exposing RelayState

Branch: pr-004-state-endpoint
- Type: feature
- Complexity: low
- Depends on: PR-001
- Priority: 3
- Coder: any

## Problem

Once the relay is running inside a container on the NAS, the only way to check whether SMS forwarding is actually alive is to read structlog output and Prometheus metrics. There is no single endpoint that answers "is the relay running, when did it start, when did it last receive an SMS, and what was the last error". `SmsRelay.state()` returns exactly this information as a `RelayState` model but it is not reachable from outside the process.

A small read-only `/state` endpoint that serializes `RelayState` to JSON closes this gap. It is consumed by `curl` for ad-hoc checks and by future Grafana panels via `json_exporter` or similar.

## Scope

Add a `/state` route to the FastAPI app that returns `relay.state()` as JSON when the relay is enabled, and returns 503 with a clear body when it is not. No authentication — the endpoint binds to LAN-only `127.0.0.1:8091` per existing settings, same trust model as `/metrics`.

Out of scope: write endpoints (no `/start`, `/stop`, `/reset`), authentication, mutation of relay state.

## Files to modify

`src/sms_gateway_v2/app.py`:
- Add an async route handler `state_endpoint(request: Request) -> Response` registered at `/state`. If `request.app.state` has a `relay` attribute, return `JSONResponse(relay.state().model_dump(mode="json"))`. Otherwise return `JSONResponse({"detail": "relay is not enabled"}, status_code=503)`.
- Register the route the same way as `/metrics` (via `app.add_api_route`).
- Use `pydantic.BaseModel.model_dump(mode="json")` so `datetime` fields serialize as ISO 8601 strings without custom encoders.

`tests/test_app_lifespan.py`:
- With `RELAY_ENABLED=false`, `GET /state` returns 503 with body `{"detail": "relay is not enabled"}`.
- With `RELAY_ENABLED=true` and mocked `build_relay` whose `state()` returns a known `RelayState`, `GET /state` returns 200 with the expected JSON shape (status, started_at, last_sms_received_at, last_error).
- Datetime fields in the response are ISO 8601 strings.

## Implementation notes

`RelayState` is a frozen pydantic model from sprint 5b. Pydantic v2's `model_dump(mode="json")` handles datetime serialization correctly without a custom encoder; `JSONResponse` wraps the dict.

Do not move `state_endpoint` into a router that requires `app.state.relay` to exist. It must work in both enabled and disabled modes — the 503 path is intentional and tested.

The 503 response body uses `detail` (FastAPI convention) rather than `error` or `message` for consistency with FastAPI's default error responses.

## Success criteria

1. `scripts/ci.sh` exits 0.
2. With `RELAY_ENABLED=false`, `curl http://127.0.0.1:8091/state` returns HTTP 503 with `{"detail": "relay is not enabled"}`.
3. With `RELAY_ENABLED=true`, `curl http://127.0.0.1:8091/state` returns HTTP 200 with a JSON body containing `status`, `started_at`, `last_sms_received_at`, `last_error`.
