# PR-016: Polish docs/deploy.md after PR-010 through PR-015

Branch: docs/pr-016-deploy-md-polish
- Type: docs
- Complexity: low
- Depends on: none
- Priority: 3
- Coder: codex

## Problem

`docs/deploy.md` was extended incrementally across PR-005, PR-010, PR-013, PR-014, and PR-015. The result is functional and complete (232 lines, full install-from-scratch flow), but four small inconsistencies remain that future operators will trip on:

1. The "Polkit configuration" section ends with a paragraph written from the perspective of "PR-014 will add a custom AppArmor profile..." — but PR-014 has been merged. The forward-looking paragraph reads as a stale TODO and conflicts with the AppArmor section that immediately follows.

2. The AppArmor verification step instructs `sudo dmesg | grep audit | tail -50`, which catches every audit subsystem line including non-AppArmor entries. A reader needs a stricter filter to actually find profile denials.

3. The "First run" section starts with `cp .env.example deploy/.env` and a comment listing the variables to set. `.env.example` ships with `RELAY_ENABLED=false` as a documented default for tests, so an operator who follows the instructions verbatim ends up with a service that refuses to start the modem relay. The minimal production .env block should be inline in the doc, not implied by a comment.

4. There is no troubleshooting note for the post-reboot scenario where ModemManager leaves the EC25 in `state: disabled` and operators must run `sudo mmcli -m 0 --enable` once before the relay can register the modem.

## Scope

A focused docs-only cleanup pass on `docs/deploy.md`. No changes to other files, no changes to source, tests, CI, deploy compose, polkit rule, AppArmor profile, runbooks, or `.env.example`.

Out of scope: restructuring sections, rewriting prose for tone, adding new operational features, automating the post-reboot modem enable.

## Files to modify

- `docs/deploy.md`

## Implementation notes

For Issue 1: remove the paragraph that starts with `PR-014 will add a custom AppArmor profile to replace apparmor=unconfined.` It is no longer accurate. Do not replace it — the AppArmor section directly below already covers the topic. The polkit section should end on the verification step.

For Issue 2: change the AppArmor verification command from
```
sudo dmesg | grep audit | tail -50
```
to
```
sudo dmesg | grep -i apparmor | tail -20
```
and add one sentence after the existing prose: `Absence of fresh DENIED entries after the recreate is the expected state.`

For Issue 3: replace the existing `cp .env.example deploy/.env` plus comment-list opening of "First run" with an explicit minimal production .env block that the operator pastes:

```
RELAY_ENABLED=true
SMS_GATEWAY_GROUP_GID=<output from getent group sms-gateway | cut -d: -f3>
TELEGRAM_BOT_TOKEN=<bot token from BotFather>
TELEGRAM_CHAT_ID=<numeric chat id, can be negative for groups>
```

Show the block inside a fenced code section, use literal `<placeholder>` markers (not real values), and instruct the operator to write it into `deploy/.env` with `chmod 600`. Mention immediately afterwards that all other variables documented in `.env.example` have safe production defaults and only need overriding if the operator wants different behavior.

For Issue 4: add a new short section titled "Modem state after host reboot" placed at the end of the document, between "Logs" and the end of the file (or before "Logs" if more contextually appropriate). The section must:

- Note that on Ubuntu 24.04, ModemManager does not consistently auto-enable USB modems on boot. After a host reboot, `mmcli -m 0` may show `state: disabled` and `signal: 0%`, which causes the relay to log `signal_read percent=0` and `registration_read registration=unknown`.
- Provide the recovery command: `sudo mmcli -m 0 --enable`.
- State that this is a known limitation and a future systemd unit (tracked separately) will automate the enable.
- Confirm that the relay container itself is healthy in this state and resumes normal operation as soon as the modem registers, no container restart needed.

Do not add a "TODO" comment, link to a hypothetical issue tracker, or otherwise commit to a future PR by name. The future systemd unit is in the operator's backlog, not the repo's.

Keep the document's existing structure, headings, code-block style, and prose voice. Do not reorder sections.
