# PR-001: Wire SmsRelay into FastAPI lifespan

Branch: pr-001-fastapi-lifespan
- Type: feature
- Complexity: medium
- Depends on: none
- Priority: 1
- Coder: any

## Problem

Sprint 5b shipped `SmsRelay` as a standalone orchestrator class but nothing constructs or starts it. `create_app` in `src/sms_gateway_v2/app.py` only mounts the FastAPI router and `/metrics`; no modem callback is wired, no worker runs, no SMS forwarding happens. To ship the service we need a factory that builds the full dependency graph and FastAPI lifespan handlers that call `relay.start()` on app startup and `relay.stop()` on shutdown. We also need a way to disable the relay during tests so the existing `/healthz`, `/`, and `/metrics` test suites keep working without a real modem on D-Bus.

## Scope

Add a `RELAY_ENABLED` setting (default `false`) that gates relay construction in `create_app`. When `false`, the app behaves exactly as today. When `true`, `create_app` builds the pipeline via a `build_relay` factory and registers FastAPI lifespan handlers.

Out of scope: the `QueueGaugeUpdater` periodic task, periodic cleanup scheduling, the `/state` HTTP endpoint, Dockerfile, deploy compose. Each of those lands in a follow-up PR.

## Files to modify

`src/sms_gateway_v2/config.py`:
- Add `relay_enabled: bool = False`.

`.env.example`:
- Add `RELAY_ENABLED=false` with a one-line comment.

`src/sms_gateway_v2/relay/factory.py` (new):
- `def build_relay(settings: Settings, metrics: MetricsRegistry) -> SmsRelay`. Constructs `ModemManagerClient`, `Queue`, `TelegramClient`, `DeliveryWorker`, and `SmsRelay` from settings.
- Validates `settings.telegram_bot_token != ""` and `settings.telegram_chat_id != ""`. Raises `RelayError` with a message naming the missing setting if either is empty.
- Does NOT enter the `TelegramClient` async context manager. The lifespan owns that.

`src/sms_gateway_v2/app.py`:
- Replace `create_app` with a version that registers a lifespan via `FastAPI(lifespan=...)`.
- On startup with `relay_enabled=True`: call `build_relay`, await `telegram_client.__aenter__()`, await `relay.start()`. Store `relay` and `telegram_client` on `app.state`.
- On shutdown: await `relay.stop()`, await `telegram_client.__aexit__(None, None, None)`.
- With `relay_enabled=False`: skip both. The app still serves `/healthz`, `/`, `/metrics`.

`tests/test_relay/test_factory.py` (new):
- Builds a `SmsRelay` from a `Settings` with non-empty credentials.
- Raises `RelayError` mentioning `telegram_bot_token` when token is empty.
- Raises `RelayError` mentioning `telegram_chat_id` when chat id is empty.

`tests/test_app_lifespan.py` (new):
- With `RELAY_ENABLED=false`, `app.state` does not have a `relay` attribute and `/healthz` returns 200.
- With `RELAY_ENABLED=true` and mocked `build_relay`, entering and exiting `TestClient(app)` calls `relay.start` and `relay.stop` exactly once.
- With `RELAY_ENABLED=true` but missing credentials, `TestClient(app)` raises `RelayError` on enter.

## Implementation notes

Validate non-empty credentials only at `build_relay` time, NOT at `Settings` construction. Tests construct `Settings()` with empty credentials all the time; validating earlier would break those tests. The lifespan path is the only place where empty credentials are a real error.

The `TelegramClient` async context manager has to be entered AFTER `build_relay` returns and BEFORE `relay.start()`. Returning a half-initialized client from the factory and entering it in the lifespan keeps `build_relay` pure and unit-testable without httpx mocks.

If `relay.start()` raises mid-startup, the lifespan must still call `telegram_client.__aexit__` to release the httpx connection pool. Wrap startup in `try/except` that does cleanup before re-raising.

## Success criteria

1. `scripts/ci.sh` exits 0.
2. With `RELAY_ENABLED=false` (default), `python -m sms_gateway_v2` starts without attempting any D-Bus connection; `/healthz` and `/metrics` work.
3. With `RELAY_ENABLED=true` and valid credentials, the lifespan calls `relay.start` on enter and `relay.stop` on exit (verified by mocked test).
4. With `RELAY_ENABLED=true` and empty `TELEGRAM_BOT_TOKEN`, the app refuses to start with a `RelayError` naming the missing setting.
