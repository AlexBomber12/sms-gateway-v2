# PR-022: Recover modem path on interface-not-found errors

Branch: fix/pr-022-modem-path-recovery-on-interface-error
- Type: bugfix
- Complexity: medium
- Depends on: none
- Priority: 1
- Coder: codex

## Problem

Production incident 2026-06-11 through 2026-06-16. The Quectel EC25 USB modem performed a USB re-enumeration (disconnect + reconnect 11 seconds later in dmesg). ModemManager re-registered the modem at D-Bus path `/org/freedesktop/ModemManager1/Modem/1` instead of the original `/Modem/0`. The relay continued to poll the stale `/Modem/0` path for 5 days, logging once per minute:

```
[warning] watchdog_poll_failed
  error='failed to query modem object interface org.freedesktop.ModemManager1.Modem on /org/freedesktop/ModemManager1/Modem/0'
```

SMS delivery silently stopped during that entire window. Operator only noticed when expected SMS did not arrive on 2026-06-16. After `docker compose up -d --force-recreate` the relay called `find_modem()` at startup, picked up `/Modem/1`, and resumed delivery.

The existing recovery path is incomplete. `_get_proxy_object` (client.py around line 747) accepts `refresh_cached_modem=True` and on `_get_proxy_object_once` failure consults `_is_unknown_object_error` (line 777-778). That predicate is true only for `DBusError.type == "org.freedesktop.DBus.Error.UnknownObject"`. If the failure surfaces in a different shape, the refresh path is not taken.

The production error string is the exact format produced by `_get_proxy_interface` (line 794, `f"failed to query {object_kind} interface {interface_name} on {object_path}"`). `_get_proxy_interface` catches all `DBUS_OPERATION_ERRORS` and raises `ModemManagerUnavailable` with no refresh attempt at all. So even when `_get_proxy_object` returned a proxy successfully on a stale path, the subsequent `get_interface(MODEM_INTERFACE)` call fails and the error never triggers re-discovery.

Result: the relay is one DBus call short of self-healing across the documented re-enumeration scenario.

## Scope

Extend the modem path refresh logic so it also triggers when the failure surfaces during `get_interface` rather than during introspection or proxy construction. After a successful refresh, the in-flight read is retried once against the new path, and added-watch subscribers are re-bound so MessageAdded continues to fire.

The fix lives in `src/sms_gateway_v2/modem/client.py`. The watchdog is not modified. Heartbeat content is not modified. Manager-level D-Bus signal subscriptions are not added.

Out of scope:
- Subscribing to `org.freedesktop.DBus.ObjectManager.InterfacesAdded` / `InterfacesRemoved` signals on the ModemManager root path. That would reduce hotplug detection latency from one watchdog interval to milliseconds but is a separate concern.
- Modifying `watchdog.py`. The watchdog already invokes `get_signal_quality` and `get_registration_state` every cycle. Once the client self-heals on those calls, the watchdog inherits the behavior with no changes.
- Adding new metrics, new heartbeat fields, or new state endpoints. Observability improvements are a separate PR.
- Changing `_drain_existing_messages`, `read_message`, or any incoming-SMS handler. Those paths also use `_get_proxy_object(refresh_cached_modem=True)` and inherit the recovery behavior once the underlying helper is fixed.
- Changing the systemd unit hardcoded `-m 0`. That is a separate concern.

## Files to modify

- `src/sms_gateway_v2/modem/client.py`
- `tests/test_modem/test_client.py` (or wherever the existing `_get_proxy_object` / `_get_proxy_interface` tests live; the implementer should discover the correct location)

## Implementation notes

### Step 1: Broaden the stale-path predicate

The current `_is_unknown_object_error` checks one specific D-Bus error type. Production showed that after re-enumeration the error reaches us through `InterfaceNotFoundError` (from `dbus_fast.errors`), not only through `UnknownObject`. Introduce a wider predicate that classifies a D-Bus failure as "the object or interface we expected at this path is no longer there, refresh the path":

```
def _is_stale_modem_path_error(self, exc: BaseException) -> bool:
    if isinstance(exc, InterfaceNotFoundError):
        return True
    if isinstance(exc, DBusError) and exc.type == UNKNOWN_OBJECT_ERROR:
        return True
    return False
```

Both `InterfaceNotFoundError` and `DBusError` are already imported and part of `DBUS_OPERATION_ERRORS` (line 80-95). Keep the existing `_is_unknown_object_error` helper unchanged for backwards compatibility with any callers that need the narrower check.

### Step 2: Extract a `_get_modem_interface` helper that handles refresh end-to-end

Today there are four call sites in client.py that do the same dance: `_ensure_modem_path` then `_get_proxy_object(refresh_cached_modem=True)` then `_get_proxy_interface(...)`. Those four are `get_modem_info` (line 260+), `get_signal_quality` (line 329+), `get_registration_state` (line 356+), and `reset` (line 382+). All four are vulnerable to the same gap: `_get_proxy_object` may succeed against a stale path, then `_get_proxy_interface` fails with a stale-path error and we surface it without refresh.

Introduce a single async helper that encapsulates the full lookup including retry:

```
async def _get_modem_interface(
    self,
    interface_name: str,
    *,
    object_kind: str = "modem object",
) -> tuple[str, object]:
    modem_path = await self._ensure_modem_path()
    modem_path, proxy = await self._get_proxy_object(
        object_kind,
        modem_path,
        refresh_cached_modem=True,
    )
    try:
        interface = self._get_proxy_interface(proxy, object_kind, modem_path, interface_name)
    except ModemManagerUnavailable as exc:
        if not self._is_stale_modem_path_unavailable(exc):
            raise
        if modem_path != self._modem_path:
            raise
        logger.info(
            "modem_interface_stale",
            modem_path=modem_path,
            interface_name=interface_name,
        )
        self._modem_path = None
        refreshed_path = await self.find_modem()
        await self._resubscribe_added_watchers(refreshed_path)
        refreshed_path, proxy = await self._get_proxy_object(object_kind, refreshed_path)
        interface = self._get_proxy_interface(
            proxy, object_kind, refreshed_path, interface_name
        )
        return refreshed_path, interface
    return modem_path, interface

def _is_stale_modem_path_unavailable(self, exc: ModemManagerUnavailable) -> bool:
    return exc.__cause__ is not None and self._is_stale_modem_path_error(exc.__cause__)
```

Refactor the four call sites listed above to use this helper. For `get_modem_info` the helper must be called once for `MODEM_INTERFACE` and once for `MODEM_3GPP_INTERFACE`; both should benefit from the same refresh behavior. Keep all existing log fields and timing instrumentation around the helper call; the helper only owns the lookup and recovery, not the higher-level structured logs.

### Step 3: Apply the same broadening to `_get_messaging_interface`

`_get_messaging_interface` (line 686+) is the entry point for `list_messages`, `delete_message`, and the `_subscribe_added_watch` path that drives MessageAdded handlers. The same stale-path scenario applies here: a re-enumeration can produce an `InterfaceNotFoundError` on the cached messaging path. The current code already calls `_get_proxy_object(refresh_cached_modem=True)` but then `_get_proxy_interface` is unprotected. Apply the same retry-after-refresh pattern. Keep the function signature `(modem_path) -> (modem_path, MessagingInterface)`.

### Step 4: Re-subscribe added watchers atomically with refresh

Today `_get_proxy_object` already calls `_resubscribe_added_watchers(refreshed_path)` on successful refresh (line 765). The helper added in Step 2 must do the same on its own refresh branch so MessageAdded subscriptions follow the path change. Without this, a re-enumeration recovery would restore signal polling but would leave incoming SMS detection broken until the next call into `_get_messaging_interface`.

### Step 5: Log events

Add one new structured log event:

- `modem_interface_stale` (info): emitted when the helper detects an interface-not-found on the cached path and triggers refresh. Fields: `modem_path`, `interface_name`.

Reuse existing `modem_found` (already emitted by `find_modem`) for the new-path confirmation. Do not add metrics in this PR.

### Behavioral invariants the implementer must preserve

- A first call against an already-stale cached path completes in at most two D-Bus round trips: one failing call to detect the stale path, one successful call against the refreshed path. No additional retries are introduced.
- If `find_modem` fails (ModemManager has no modem at all), the helper raises `ModemNotFound` as today. The watchdog already logs `watchdog_poll_failed` in that case and continues polling, which provides natural recovery once ModemManager sees the modem return.
- Refresh is only attempted when the failing path equals `self._modem_path` at the time of failure. If a caller passes some unrelated path (for example a stale SMS object path from before the re-enumeration), the failure surfaces as today. This matches the existing `refresh_cached_modem` semantics in `_get_proxy_object`.

## Tests

The implementer must add or update these tests in the existing test file for `ModemManagerClient`:

1. `test_get_signal_quality_recovers_from_interface_not_found_on_cached_path`: configure the dbus-fast mock so the first `proxy.get_interface(MODEM_INTERFACE)` call raises `InterfaceNotFoundError`. The next `find_modem` returns a new path `/Modem/1`. `get_signal_quality` succeeds against the new path. Assert: `find_modem` was called exactly once during recovery, `_modem_path` updated to the new value, the returned `SignalQuality` came from the second call, and `_resubscribe_added_watchers` was invoked with the new path.

2. `test_get_signal_quality_does_not_recover_when_path_is_not_cached`: pre-set `self._modem_path` to `/Modem/0`. Force the helper to be called with a different path string (simulate concurrent change). The interface-not-found error should propagate without triggering refresh.

3. `test_get_signal_quality_propagates_when_find_modem_fails`: first call raises `InterfaceNotFoundError`, second `find_modem` raises `ModemNotFound`. Caller observes `ModemNotFound`. Assert no infinite retry, no swallowed exception.

4. `test_get_signal_quality_propagates_other_dbus_errors_unchanged`: first call raises a generic `DBusError` whose type is neither `UnknownObject` nor `InterfaceNotFoundError`. `_is_stale_modem_path_error` returns False. Caller observes the original `ModemManagerUnavailable`. No refresh attempted.

5. `test_get_registration_state_recovers_from_interface_not_found_on_cached_path`: same shape as test 1 but for `Modem3gpp` interface and `get_registration_state`. Verifies the helper is wired into the second call site, not only into the signal call site.

6. `test_list_messages_recovers_from_interface_not_found_on_cached_path`: simulate `InterfaceNotFoundError` on `_get_messaging_interface` first call. After refresh, `list_messages` returns the message list from the new path.

7. `test_delete_message_recovers_from_interface_not_found_on_cached_path`: same as test 6 but for `delete_message`. After refresh, the delete completes against the new modem path.

8. `test_message_added_subscription_follows_modem_path_after_refresh`: register an added-watch callback. Trigger a refresh via interface-not-found on the cached path. Assert that `messaging.on_added` was called against the new path's messaging interface, and that `_added_watch_keys` now contains `(new_path, callback_key)`.

9. `test_unknown_object_error_path_still_triggers_refresh`: regression test for the existing `_is_unknown_object_error` path. Verify that the old behavior is preserved bit-for-bit: a `DBusError(type=UNKNOWN_OBJECT_ERROR)` raised from `_get_proxy_object_once` triggers refresh through the same flow.

All tests must run without a real D-Bus session; use the existing mock harness for `MessageBus`, `ProxyObject`, and the interface protocols. Do not add integration tests against ModemManager.

## Success criteria

- A new helper `_get_modem_interface(interface_name, object_kind="modem object")` exists on `ModemManagerClient` and is used by `get_modem_info`, `get_signal_quality`, `get_registration_state`, `reset`, and the modem-interface lookup inside `_get_messaging_interface`.
- A new predicate `_is_stale_modem_path_error` exists and recognizes both `InterfaceNotFoundError` and `DBusError(type=UNKNOWN_OBJECT_ERROR)`. The narrower `_is_unknown_object_error` helper is preserved for backwards compatibility.
