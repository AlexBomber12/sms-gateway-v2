# PR-021: Hybrid wait-and-poll for SMS Text in read_message

Branch: fix/pr-021-sms-text-hybrid-poll
- Type: bugfix
- Complexity: medium
- Depends on: none
- Priority: 1
- Coder: codex

## Problem

PR-011 introduced `ModemManagerClient.read_message` with a subscribe-and-wait pattern on PropertiesChanged to handle the documented ModemManager race where MessageAdded fires before the Text property is populated. The fix works for most incoming SMS, but real-world production data over 2 days reveals a 25 percent miss rate (1 of 4 inbound SMS still produces an empty text in the persisted queue item):

```
1778484914039-3e93a2d88b2c454693382e84365c01f4.json:
  number: 900
  text: ""
  timestamp: 2026-05-11T10:35:04+03:00 (modem-side)
  enqueued: 2026-05-11T07:35:14.039 UTC (10 seconds after modem timestamp)
```

The 10-second gap between modem timestamp and our enqueue is consistent with the read_message waiting the full `MODEM_SMS_TEXT_WAIT_TIMEOUT_SECONDS=5` and then falling through with empty text. This means our subscribe-and-await PropertiesChanged path is NOT receiving a signal for this SMS, or is missing one due to a subscription race.

Two complementary failure modes are possible:

1. The Quectel EC25 firmware path that ModemManager uses for some SMS does NOT emit a Text PropertiesChanged signal; the value goes directly from internal-pending to populated via a different code path inside ModemManager. In this case our subscriber will wait forever no matter how long the timeout is.

2. There is still a thin race between MessageAdded signal handler invocation and our `subscribe to PropertiesChanged` call: if Text populates in those microseconds, the subscribe sees nothing afterward.

A simple timeout bump does not help either case. The robust fix is to poll the property in parallel with the signal wait, so we discover a populated Text whether or not the signal fires.

## Scope

Replace the pure subscribe-and-wait inside `ModemManagerClient.read_message` with a hybrid pattern: subscribe FIRST (avoid race 2), read Text immediately (zero-latency success path), then loop with short sub-timeouts that poll the property regardless of whether the signal fires (covers race 1). Total max latency unchanged; minimum-latency case unchanged; the previously broken "no signal" case becomes recoverable.

Out of scope: changing the public method signature, adding new metrics, restructuring the relay path that calls read_message, touching the watchdog / cleanup / heartbeat schedulers, adjusting the configurable timeout default (keep at 5 seconds, can be raised by operator if needed via env).

## Implementation notes

Refactor the body of `read_message(sms_path)` to follow this control flow precisely:

1. Resolve SMS interface via the existing `_get_sms_interface(sms_path)` helper.
2. Read PduType; if not in `INBOUND_SMS_PDU_TYPES`, return None as today.
3. Subscribe to PropertiesChanged on the SMS object FIRST, capturing the asyncio.Event that the existing helper sets when Text changes. Do NOT read Text yet. The subscribe-first ordering is critical: any path where the signal fires between read and subscribe is now safe.
4. After the subscribe is in place, read Text. If non-empty, build IncomingSms and return immediately. Total latency in this happy path is one D-Bus round trip; no change from current behavior.
5. If Text is empty, enter a polling loop bounded by `MODEM_SMS_TEXT_WAIT_TIMEOUT_SECONDS`. Each iteration of the loop:
   a. `await asyncio.wait_for(event.wait(), timeout=poll_interval)` with `poll_interval = 0.5` seconds. Catch `asyncio.TimeoutError` and continue.
   b. Re-read Text regardless of whether the event fired or the wait timed out. This is the key change: we no longer trust the signal as the sole trigger.
   c. If Text is now non-empty, build IncomingSms and return.
   d. If the cumulative elapsed time since loop start exceeds the configured timeout, break out of the loop.
6. After the loop, if Text is still empty, log a structured `sms_text_wait_timeout` warning identical to the current implementation, build IncomingSms with empty text, return.
7. Always unsubscribe from PropertiesChanged in `try/finally`, regardless of which branch returned.

The `poll_interval` of 0.5 seconds is hardcoded inside read_message; do NOT add a new configuration setting for it. Operators tune the total timeout, not the polling cadence; the cadence is an implementation detail. Add a brief code comment naming the trade-off (smaller poll = more D-Bus traffic but faster non-signal recovery; larger poll = less traffic but slower fallback).

Keep the existing `message_read` info log event and `sms_text_wait_timeout` warning event names and field shapes. Do NOT introduce new event names; downstream log consumers (and our own historical debugging) should see the same shape.

Verify that the existing `MODEM_SMS_TEXT_WAIT_TIMEOUT_SECONDS=5` continues to be the public-facing setting. If the previous implementation calls a private `_sms_text_wait_timeout_seconds` instance attribute as an override path, keep that wiring untouched.

## Tests

Refactor and extend the existing read_message tests:

1. Update `read_message_returns_text_immediately_if_already_populated`: mock now reads Text once after subscribe and finds it non-empty. Assert no polling loop iterations occurred (e.g., via a poll counter on the Text getter mock).

2. Update `read_message_waits_for_text_then_returns`: mock fires PropertiesChanged after a short delay. The event-driven path completes in well under the timeout. Assert the loop exited via event (not via poll-induced re-read).

3. **NEW** `read_message_recovers_when_no_signal_fires`: mock NEVER fires PropertiesChanged but Text populates on the second Text read. Method must succeed via the polling fallback. Assert at least one full poll_interval elapsed and that the returned IncomingSms has the populated text. This is the new regression test for the production miss case.

4. Update `read_message_logs_warning_and_returns_empty_on_timeout`: mock never populates Text, never fires the signal. Method logs `sms_text_wait_timeout` and returns IncomingSms with empty text. Assert total elapsed time is approximately the configured timeout (with reasonable jitter).

5. `read_message_skips_non_inbound_pdu`: unchanged behavior; assert.

6. **NEW** `read_message_subscribes_before_first_read`: assert call ordering — the PropertiesChanged subscription is established before the first Text read. This closes race 2.

7. **NEW** `read_message_unsubscribes_on_all_exit_paths`: parameterized test that verifies the finally block runs for: happy path return, polling-discovered return, signal-discovered return, timeout fallthrough return, and an in-flight exception from the SMS interface. Each case must call unsubscribe exactly once.

All existing modem coverage must remain at 100 percent.
