# PR-009: Lifespan shutdown cleanup, single shutdown timeout, HOST override hardening

Branch: pr-009-lifespan-cleanup
- Type: refactor
- Complexity: low
- Depends on: none
- Priority: 4
- Coder: any

## Problem

Three small papercuts found during the post-PR-001..008 review. None of them block production but all are easy to fix in one pass.

1. **`_shutdown_relay` is procedural copy-paste.** `src/sms_gateway_v2/app.py` has the same six-line "stop scheduler → `wait_for` → on timeout cancel and suppress" block repeated four times in `_shutdown_relay`, once per background task (gauge updater, cleanup scheduler, watchdog, heartbeat). Diffs through this code in six months will be painful and error-prone.
2. **Four constants are the same value.** `GAUGE_TASK_SHUTDOWN_TIMEOUT_SECONDS`, `WATCHDOG_TASK_SHUTDOWN_TIMEOUT_SECONDS`, `CLEANUP_TASK_SHUTDOWN_TIMEOUT_SECONDS`, `HEARTBEAT_TASK_SHUTDOWN_TIMEOUT_SECONDS` are all defined as `2.0`. There is no scenario where they would diverge.
3. **`HOST` env-var foot-gun in Docker.** The Dockerfile sets `ENV HOST=0.0.0.0`, but `deploy/docker-compose.yml` reads from `env_file: - .env`. If the operator copies `.env.example` (which ships `HOST=127.0.0.1` for local dev) to `deploy/.env` without editing the line, Compose's `env_file` overrides the image `ENV` and uvicorn binds to the container's loopback only. The healthcheck inside the container still passes (curl also goes to loopback), but `curl http://192.168.50.2:8091/state` from outside the host fails with connection refused. `docs/deploy.md` warns about this in a comment, but a config-level fix is cleaner.

## Scope

Refactor `_shutdown_relay` to a single `_stop_background_task` helper. Collapse the four shutdown-timeout constants into one. Pin `HOST=0.0.0.0` in the compose file at a precedence level that `.env` cannot override.

Out of scope: rewriting `_startup_relay` (the linear setup is fine as-is), adding new env vars, changing public behavior, changing test fixtures.

## Files to modify

`src/sms_gateway_v2/app.py`:
- Replace the four `*_TASK_SHUTDOWN_TIMEOUT_SECONDS = 2.0` module-level constants with one `BACKGROUND_TASK_SHUTDOWN_TIMEOUT_SECONDS = 2.0`.
- Add a `typing.Protocol` named `SupportsStop` with a single sync `stop(self) -> None` method (matches the four scheduler classes).
- Add a helper `async def _stop_background_task(scheduler: SupportsStop, task: asyncio.Task[None], timeout: float = BACKGROUND_TASK_SHUTDOWN_TIMEOUT_SECONDS) -> None` that calls `scheduler.stop()`, awaits the task with `asyncio.wait_for`, and on `TimeoutError` cancels and suppresses `(asyncio.CancelledError, Exception)` while awaiting completion. This is the same pattern used four times today.
- Replace the four shutdown blocks in `_shutdown_relay` with calls to the helper. The heartbeat block keeps its existing `if heartbeat_scheduler is not None and heartbeat_task is not None:` guard.
- Order of stops stays the same: gauge updater → cleanup scheduler → watchdog → heartbeat → `relay.stop()` → `telegram_client.__aexit__`.

`deploy/docker-compose.yml`:
- Add an `environment:` block under the service with `HOST: "0.0.0.0"`. Compose precedence makes `environment:` override `env_file:`, so this neutralizes a stray `HOST=127.0.0.1` in `deploy/.env`.
- Update the leading comment block: remove the warning about manually setting `HOST=0.0.0.0` (no longer required) and replace with a one-liner noting that the compose file pins `HOST` at the service level.

`docs/deploy.md`:
- Update any line that tells the operator to set `HOST=0.0.0.0` in `deploy/.env`. The new instruction is "leave `HOST` unset or any value — the compose file pins it to `0.0.0.0`."

`docs/migration-from-v1.md`:
- Same `HOST` instruction update in the pre-flight section.

`README.md`:
- No status bump (the roadmap is already complete). Optionally append a "Maintenance" subsection note that PR-009 is a follow-up cleanup; skip if it adds noise.

## Implementation notes

The four background-task scheduler classes (`QueueGaugeUpdater`, `CleanupScheduler`, `ModemWatchdog`, `HeartbeatScheduler`) each have a sync `stop()` method. A `Protocol` with `stop(self) -> None` types the helper without forcing a shared base class — keeps the existing class hierarchy untouched. Use `typing.Protocol` and `@runtime_checkable` is NOT needed (we never `isinstance`-check; we only pass concrete instances at the call site).

Existing `tests/test_app_lifespan.py` already covers the gauge-task-timeout cancellation path. It must keep passing without modification — that is the proof that the refactor preserves behavior. If a test references the removed constant by name (`GAUGE_TASK_SHUTDOWN_TIMEOUT_SECONDS`), update the import to the new constant; do not introduce new tests.

For the compose `HOST` pin, the precedence is documented:
- Image `ENV` (lowest)
- `env_file` (middle)
- `environment:` (highest, wins)

Pinning at `environment:` is the right level — it survives the user setting `HOST=` in `deploy/.env` to anything. Removing `HOST=127.0.0.1` from `.env.example` would also work but breaks local dev where `python -m sms_gateway_v2` should default to loopback. Compose-level pin is the smaller change.

The `docs/migration-from-v1.md` mention of `HOST=0.0.0.0` in pre-flight step 2 is now wrong (was a workaround for the old foot-gun). Remove the line.
